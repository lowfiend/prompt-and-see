# to-mvp — 真相 → 畫面

讀取 `behaviors/<slug>/` 的場景檔與行為地圖，生成 MVP HTML 到 `behaviors/<slug>/mvp/`（單檔 `index.html` 優先），讓人在寫任何正式程式之前，就能親眼看到並操作這個功能。

## 前置檢查（不通過就停）

- `map.md` 檔頭必須是 `狀態: 已凍結`。未凍結 → 停下來告訴使用者先用 `/map-it` 走完找碴與凍結。**不在未凍結的真相上蓋房子。**

## 視覺層委派（好看是別人的專業，行為不漏是本 skill 的）

按優先序決定畫面的視覺處理：

1. `behaviors/config.md` 有設定 **UI 設計 skill** → **明確呼叫它**取得設計系統（風格、配色、字型、版式），照它的產出刻畫面。不碰運氣等自動觸發。
2. 沒設定但 config 指定了**設計系統文件**（如 `DESIGN.md`、元件庫規格＋共用 CSS）→ 對齊它。
3. 都沒有 → 乾淨的中性樣式，不自創視覺語言。

設計系統是**模子**：生成時讀取、把需要的樣式**印進** MVP。MVP 帶走的是快照，不連結原檔——模子更新了，重生 MVP 即可。

## 覆蓋規則（本 skill 的核心）

**地圖上有幾個節點，MVP 就要做出幾個看得到的狀態**——包括每一條標紅的失敗路徑：

- 畫面節點（📄）→ 一個可導覽到的頁面或區塊
- 按鈕節點（🔘）→ 真的能點，點了走場景寫的那條線
- 失敗／例外狀態（❌）→ 可觸發或可切換檢視（例如用假資料開關模擬「查無結果」「服務錯誤」）

完成後輸出**覆蓋對照表**：地圖節點 × MVP 狀態，一行一節點，缺的標出來——漏做哪個錯誤狀態，一眼看見。

## 依賴功能的入口：假入口 stub

- 地圖上的**外部入口節點**（別的功能的畫面）→ MVP 用**最小假入口**表現：明確標注「模擬：入口行為屬 `<來源功能>`」，點它進入本功能主體。
- **禁止複製其他功能的 MVP**——兩份快照必然漂移成謊言。
- **禁止跨資料夾連結**——單獨交付本資料夾時連結會斷。

## MVP 必須自足

- CSS／JS 內嵌單檔；圖片用 data URI，或放在自己的 `mvp/` 資料夾內。
- **禁止引用需求資料夾外的任何資源**（共用 assets、其他功能的檔案、CDN）。
- 一致性來自生成來源（設計系統模子），不來自共用檔案。生成物的重複無害——手寫物的重複才是病。

## 總覽頁

MVP 完成後，依 `behavior-mapping` 的總覽頁規則重生 `behaviors/index.html`（規格與分區定義以它為準——總覽的重生職責歸它一家管，本 skill 的責任是讓 MVP 連結生效）。

## 驗證

有瀏覽器工具就逐狀態截圖，對照地圖驗版面、顯隱、RWD；沒有就在覆蓋對照表註明「未截圖驗證」。

## 硬規則

- **不發明行為**：場景裡沒有的按鈕、流程、文案一律不出現。想到「應該還要有」的東西 → 提出來，走回場景檔（那是 `/map-it`／`/remap` 的事）。
- **假資料要一眼看得出是假的**（例如商品名用「範例商品 A」），避免被當成真實內容流出去。
- MVP 是生成產物：場景改了就重新生成，不在 MVP 上手改行為。

完成後指路：下一棒通常是 `/to-handoff`（以整個需求資料夾交付）；看了畫面想改行為 → `/remap`。
