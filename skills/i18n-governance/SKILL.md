# i18n-governance — 文字紀律

使用者看得到的每一句話都是資產：集中管理、語意命名、可審查。本紀律管文字的**家**與**名字**，不管文案寫得好不好。

> 宿主專案的 CLAUDE.md 與慣例檔（含既有 key 命名慣例）是最終權威；本紀律是預設值，衝突時以宿主為準。

## 鐵則（紅線）

- **不寫死**：使用者可見文字不准直接寫在 UI code 裡——一律走專案核可的資源／在地化機制。
- **不串接**：不准用字串串接組句；動態值用具名佔位符。例（產業中性，僅為例）：`orders.cancel.countdown.text` 配 `{{seconds}}`，而不是 `"可取消時間剩 " + seconds + " 秒"`。
- **不洩漏**：敏感資訊遮罩或最小揭露；後端與第三方訊息直出畫面前，先過一次顯示安全。

## key 命名

- 結構化：`[namespace].[feature].[element].[type]`（分隔符依平台慣例；小專案可以更短，但同一專案只用一套結構）。
- 命名描述**語意**，不描述外觀；不用拼音、不用看不懂的縮寫。
- **同義複用**：同一個確認過的語意共用同一個 key——確認、取消、重試、關閉這類全域動作用共用 key；同義漂移成多個 key 是紅線。
- 臨時 key 用明確前綴標示（例：`temp.`），不得與正式 key 混用；本次改動交付前清掉，不准留給下一個人。
