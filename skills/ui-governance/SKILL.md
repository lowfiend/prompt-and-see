# ui-governance — 介面紀律

介面的一致性來自**語意**，不是每頁重新配色。本紀律管可維護與可用；不管美學方向——那是設計探索的事。

> 宿主專案的 CLAUDE.md 與慣例檔（設計系統、screen spec）是最終權威；本紀律是預設值，衝突時以宿主為準。

## 語意優先

- 按鈕分語意變體：**primary**（確認、送出、繼續）、**secondary**（返回、放棄目前操作）、**destructive**（危險動作——醒目區隔，不得與 primary 混淆）。變體按**後果**判定，不按字面：關閉對話框的「取消」是 secondary，取消一筆業務物件是 destructive。
- 對話框、標籤、tab 用共用的語意變體；同一個語意動作在不同畫面不得長得不一樣，除非有記錄的理由。
- 顯示資料也講語意：不暴露對使用者無意義的內部識別碼，顯示語意字串（名稱＋關鍵屬性）；對使用者有意義的領域編號不在此限。

## 鐵則（紅線）

- **token 管有語意的值**：重複出現、跨元件、或承載設計語意的顏色、字級、間距、圓角、陰影走 token／theme；單一元件的一次性數值留在元件內——**不准為湊 token 而搬家魔數**。選取類控件（tab、chip、filter）要同時定義選取與未選取兩態的 token。
- **重複抽共用**：同語意模式出現兩處以上就評估抽共用元件——語意穩定才抽，不抽要留得住理由；開新的局部元件前，先搜尋既有的同語意控件，找得到就重用。
- **狀態可見**：本次行為所需的狀態（場景要求的，或技術上不可避免的，如非同步的載入中）要肉眼可分辨——loading、空、錯誤、disabled、選取、成功皆屬此類；**不得因這份清單自行新增場景沒有的產品狀態**。顏色不得是唯一訊號；確認動作要有明確的成功回饋。
- **不遮內容**：固定 header／footer／overlay 不得蓋住可互動內容；safe area 要處理；文字型控件不寫死寬度，長字串與在地化文案要真的測過，不是假設不會爆。
- **無障礙**：可互動元素要有可及名稱與可見焦點態；觸控目標符合平台規範。

## Brownfield 一條

改寫或搬遷既有產品時，**既有產品是綁定的 UI 契約**：版面、圖示、互動順序、狀態語意先保真，再談平台友善的抽象——「差不多像」不等於一致。
