# to-spec — 場景 → 極簡 spec

BDD 場景是行為的原始碼；spec 只補場景不管的事，小到不需要框架。本 skill 不管下游用什麼規格工具——RD 有自己跑順的工具，直接拿場景檔當他們流程的輸入即可，不需要本 skill（接縫紀律寫在 handoff 的 RD 提示：行為以場景檔為準，工具只准補技術節）。使用者呼叫就依當前場景生成，沒有前置條件。

> 設定檔住 `behaviors/config.md`（「場景資料夾」欄位決定實際根目錄，本文以預設 `behaviors/` 行文）；沒有設定檔就用預設值。

## 產出

`behaviors/<slug>/spec/spec.md`，只有四節：

1. **行為**：直接照搬場景內容——場景就是行為描述與驗收標準，不改寫，不准只挑「重點場景」。
2. **技術決定**：語言與框架（既有 repo 就是既定事實，不問）、架構、API 形狀、資料庫、資料的時間語意（快照或連動）、測試接縫等場景不管的事——依 `interviewing` 紀律向技術負責人訪談補齊，不准腦補技術決策；對方不在場，就把選擇題清單（含推薦答案）寫進此節當 TODO，答案回來再跑一次本 skill 填入。RD 自己跑本 skill 最順——訪談對象就是自己，當場答完。**不寫檔案路徑與程式碼片段**——它們腐得比決定快，寫決定本身。
3. **拆票**：把場景拆成**垂直切片**的工作項——每票切穿完成它所需的所有層面，做完可單獨展示，不是「一層一票」；大小以塞得進一個 context window 為度。每票標注 **Blocked by**（被哪些票擋住；沒被擋的票可立刻開工），驗收標準直接引用場景名稱——**場景即驗收**，不另寫驗收清單。共同地基（前置重構、共用基礎）不准藏進功能票裡——夠小就併入第一張用到它的票並在票面明列，否則獨立成票、其他票 Blocked by 它；地基票以自身可執行的工程檢查（建置、煙霧測試）驗收，下游場景事後承接。票按依賴序編號、blockers 在前。只依行為拆。
4. **不做什麼**：刻意排除的範圍，防施工時腦補擴張——來源是場景檔 feature description 的「不做」段、場景界線與本次訪談確認的排除項，不自行發明。

檔頭一行：「本檔由需求資料夾的場景檔生成——行為要改請改場景檔後重生。」（實際路徑依當前需求資料夾，不照抄本文的預設路徑。）

## 重生規則

行為、拆票兩節永遠由當前場景重出；技術決定、不做什麼兩節沿用前一版已定案的內容，只對新缺口補問——已定案內容與當前環境事實衝突時，事實照實更新、不問；因事實改變而重新開放的取捨才訪談。行為以場景檔為準，技術與排除項以訪談定案為準。

## 硬規則

- 單向生成：絕不從 spec 反向改場景。
- 行為的家在場景檔：訪談中冒出新行為，回 `/map-it` 討論，不寫進 spec。
