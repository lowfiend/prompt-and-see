# image-governance — 圖像資產紀律

圖跟文字一樣，名字要有紀律：看檔名就知道它是誰的、住哪裡；換皮、白牌、模組替換時**按命名家族整批換**，不會換漏、不會換錯。

> 宿主專案的 CLAUDE.md 與慣例檔是最終權威；本紀律是預設值，衝突時以宿主為準。

## 命名

- 結構化：`[namespace]_[feature]_[element]_[state]`（分隔符依平台資源限制調整，語意結構不變）。
- **狀態寫明**：default、active、disabled、selected 等變體命名一致，同一家族排得整齊——家族命名不一致，整批替換時就會換漏。
- **通用資產用通用命名**：logo、返回鍵、預設頭像這類跨功能的通用件，不掛在任何 feature 名下。
- 命名描述語意，不是個人習慣的隨手縮寫。小專案可省略沒有區辨力的段，但同一專案只用一套結構。

## 歸屬

- 共用資產住 shared／common；功能專屬資產（某功能的主視覺、活動圖）住該 feature。未拆目錄的小專案，歸屬由檔名的 namespace 前綴承載（通用前綴 vs 功能前綴），不必為歸屬而開目錄。
- **重用成真才升 shared**——「可能有人會用」不算；一個資產被多個 feature 用到時，重新評估歸屬。
- 發現共用件藏在某個 feature 裡，搬到正確歸屬並同步更新引用。

## 引用

- 同一資產的路徑不得散落在多個檔案；資產變多、需要動態映射或整批替換時才集中成對照表——單一靜態引用照宿主慣例即可，不為一張圖建間接層。
- **改名＝同時更新全部引用**；缺檔、斷連是紅線，不是瑕疵。
- 缺檔與命名漂移在交付前就要抓出來，不留到 runtime 才發現。
