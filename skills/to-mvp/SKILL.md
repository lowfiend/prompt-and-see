# to-mvp — 場景 → 可操作的畫面

把目前的 BDD 場景做成**免安裝、免編譯、直接打開就能操作**的靜態 HTML MVP，讓人在寫任何正式程式之前，親眼看到、親手走過每個行為。

> 設定住 `behaviors/config.md`（「場景資料夾」決定場景根目錄，本文以預設 `behaviors/` 行文）；沒有設定檔就用預設值。MVP 固定住 `behaviors/mvp/`，不可配置。

## MVP 的固定技術邊界

一律是靜態 HTML：**不需要 Node.js、不需要 npm install、不需要 build**——使用者直接打開入口 HTML 就能操作。

- 允許：HTML、CSS、原生 JavaScript、圖片與本地字型、多個頁面、`assets/` 共用資源。
- 一律用相對路徑；整個 MVP 資料夾複製到任何地方都能直接開啟。
- 「純 HTML」不代表全部塞進單一檔案——多頁＋`assets/` 都可以，只要不需要工具鏈。

## MVP 的位置（固定）

MVP 固定住 `behaviors/mvp/`，入口固定是 `behaviors/mvp/index.html`——不搜尋、不推測、不配置其他路徑。

- **`behaviors/mvp/` 已有內容** → **原地增量修改**：保留既有目錄結構、樣式與無關功能。
- **不存在或為空** → 建立最小 MVP：只實作目前場景所需的功能與狀態。後續需求都在同一份上增量修改。
- **使用者提供其他位置的靜態 HTML**（例如設計稿轉出的檔案）→ 動手前說明會放入 `behaviors/mvp/`，同意後再進行：
  - 與 `behaviors/mvp/` 既有內容發生**實際衝突** → 列出衝突檔案與影響，讓使用者決定保留、替換或合併——不建立通用合併協定或衝突紀錄。
  - 提供的檔案用其他入口檔 → 詢問使用者要以哪個檔案為主，把選定的入口整理為 `index.html`，並同步修正受影響的相對連結。

repo 另有 React／Vue／Next.js 等正式產品 code 時：可以**閱讀**它作為視覺與既有脈絡參考；不修改、不要求啟動正式產品；交給使用者操作的 MVP 仍是獨立的靜態 HTML，不宣稱它等於正式產品實作。

## 動手前：摘要＋確認

修改前向使用者摘要三件事：

1. 本次理解的行為（對應哪些場景）。
2. 預計新增／修改哪些頁面或部分。
3. 哪些既有功能不動。

使用者同意才動手。**這個確認留在對話裡就好——它是動手前的對話，不是需要被持久化的流程狀態。**

## 實作規則

- **不發明行為**：場景沒要求的新業務行為不出現；導覽等鷹架可以有，但不藉此夾帶行為。
- **保留無關既有功能**：場景沒寫到的既有頁面與功能原樣保留——場景描述目前需求，不是全 app 的總帳。
- **場景中描述的成功、失敗、空資料與邊界狀態，都要做得出來、看得到**（例如用假資料開關模擬「查無結果」「服務錯誤」）。實作時發現場景有明顯缺漏 → 先詢問使用者，不自行補進 MVP。
- **鷹架不冒充產品**：狀態切換等檢視控制是開發鷹架、不是產品 UI——與畫面內容物理隔離（例如浮動、預設收合、可挪開的小面板，純靜態就做得到），並明確標示「原型預覽・非正式 UI」；不得內嵌在內容流的卡片或對話框裡——那會被誤認為產品功能。
- **文案**：場景釘死的文字照抄；場景沒釘死、畫面又必需的（欄位標籤、佔位字、提示語）補中性文案，不藉補文案夾帶行為。
- **假資料要一眼看得出是假的**（例如商品名用「範例商品 A」），避免被當成真實內容流出去。

## 完成前驗證

- 檢查所有相對連結與資源都存在、不斷鏈。
- 有瀏覽器工具就實際打開入口頁，走一遍主要情境與失敗狀態；沒有就如實告訴使用者尚未實測。

## 完成後回報

告訴使用者：入口是 `behaviors/mvp/index.html`（直接打開就能操作）、本次改了什麼、失敗／空狀態怎麼觸發。想改就繼續下指令；要交接 → `/to-handoff`。
