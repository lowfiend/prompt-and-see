# domain-language — 領域語言紀律

讓整個專案——對話、場景、文件、程式碼——用同一套詞。詞彙表住在專案根目錄的 `CONTEXT.md`。

## 讀（每次動工前的一行習慣）

- `CONTEXT.md` 存在就先讀。訪談用詞、場景用詞、檔名、產出文件，一律沿用它的詞彙。
- 自己用了 Avoid 清單裡的詞，當場自我糾正。

## 寫（詞定案的當下，不批次）

一個行話的定義被拍板的瞬間（例：「有效訂單＝已付款且未取消，退貨處理中也算有效」），**當場**寫入 `CONTEXT.md`，格式：

```markdown
**有效訂單**：
已完成付款且未取消的訂單；已申請退貨但尚未退款完成也算有效。
_Avoid_: 成立訂單、active order
```

- **懶建立**：檔案不存在時，第一個詞定案才建立，不預開空檔。
- **只放詞彙，僅此而已**：不放行為與行為決定（場景檔的事）、不放實作細節。
- **建檔與寫入一律依 [CONTEXT-FORMAT.md](./CONTEXT-FORMAT.md) 的骨架**（檔案標題為「# <專案名>」、三區塊結構）——第一次建檔前先讀它，不憑印象發明格式。

## 主動維護（訪談進行中）

- **挑戰衝突**：使用者的用詞跟詞彙表矛盾時立刻指出——「詞彙表定義『有效訂單』含退貨處理中，但你剛剛的意思似乎不含——是哪個？」
- **精確化模糊詞**：使用者用了一詞多義的詞（「使用者」指買家還是後台管理員？），提出精確的候選詞讓使用者拍板。

## 界線

- ADR（難回頭的技術決定）不歸這裡——技術決定屬於下游。
- 行為決定（「不需登入」）也不歸這裡——那寫進場景檔（或其 feature description）。
