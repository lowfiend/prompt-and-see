# CONTEXT.md 格式

`CONTEXT.md` 是專案的詞彙表——只放詞彙，不放行為（場景檔）、不放決定（地圖檔頭）、不放實作細節。三個區塊，**有內容才出現**（懶建立原則同樣適用於區塊）。

> 活範例：本 repo 根目錄的 [`CONTEXT.md`](../../CONTEXT.md)——我們自己的詞彙表就用這個格式。

## 區塊一：Language（詞條）

每個詞條三件事：詞、定義、禁用詞。

```markdown
**<詞>**：
<一到三行定義，寫到「能仲裁爭議」的精確度——讀完能回答這個詞的邊界問題>
_Avoid_: <被淘汰的同義詞、舊講法，以頓號分隔>
```

- 定義的驗收標準：團隊裡兩個人對這個詞吵起來時，讀這條就能判誰對。
- `_Avoid_` 列出禁用詞；agent 或人用了就該被糾正。
- 新詞條放在語意相關的詞附近，不強制排序。

## 區塊二：Relationships（詞與詞的關係）

一行一條，用粗體標詞：

```markdown
## Relationships

- 一個 **<詞A>** 含多個 **<詞B>**
- **<詞C>** 是 **<詞D>** 的前置條件
```

只放「會影響理解」的關係，不畫完整資料模型（那是下游的事）。

## 區塊三：Flagged ambiguities（歧義判決）

吵過架的詞和判決結果，防止舊爭議復活：

```markdown
## Flagged ambiguities

- 「<舊詞>」曾同時指 <甲義> 與 <乙義>——已解決：<甲義> 叫 **<新詞>**；
  「<舊詞>」不再是本專案用詞。
```

## 完整骨架

```markdown
# <專案名>

## Language
（詞條……）

## Relationships
（關係……）

## Flagged ambiguities
（判決……）
```
