# reproducing — 可重現紀律

一個 finding 是一個**主張**，不是事實。主張要先跑出來、看得到、留得下紀錄，才算問題；算問題才准改 code；改完用同一組步驟再跑一次，才算修好。沒跑出來就動手，改對改錯都無從判斷。

> 宿主專案的 CLAUDE.md 與慣例檔是最終權威；本紀律是預設值，衝突時以宿主為準。

## 何時進門

下一步可能改 code、而理由是「某段行為不對」時，都走這裡：

- 收到問題回報（使用者、issue、測試人員說壞了、不對、很慢、有時候會）
- 審查產出 finding（自審、code review 工具、子代理回報「這裡可能有問題」）
- 自己讀碼起疑，手癢想順便改
- **一批 code 改完、準備回報之前**——沒有人主張任何事，自己去找：重讀這批 diff，列出可能的問題，每條都走下面的流程，直到沒有新的已重現才回報

不走這裡的：寫新功能（場景與 tdd 的事）、純風格與命名的 finding（照慣例改即可，無需重現）、使用者直接指定改某個明確的東西。

## 來源不分級，證據才分級

**所有主張進門時都是同一級：待校驗。** 使用者親口說的、issue 寫的、子代理回報的、審計文件結論的、自己讀碼推出來的，一視同仁。校驗跑過才分兩路：

```
主張（不分來源）
  └─ 校驗：跑儀器、留紀錄
       ├─ 已重現：現在能跑、能看到、紀錄在手   → 可以修；這組步驟就是驗收尺
       └─ 未重現：試過了跑不出來                → 不改；列出試了什麼
```

- **使用者說的也要校驗**。先跑出來、把紀錄拿給使用者看「與你說的一致」或「與你說的不一致」，再動手。照一個未經校驗的描述改，改錯了比沒改更糟。
- **子代理回來的每一條都是主張**。子代理說「我跑過測試、通過了」也是主張：主代理重跑那一個指令或親眼看它的輸出。派子代理時給 diff 與契約，不給自己的結論——帶著假設出去的子代理回來只是把假設確認一次。
- **否定式結論也是主張**：「無問題」「已對照」「保留」「與參考一致」最容易藏漏，因為看起來不需要動作。抽驗時優先抽這些。另一份文件的判定不能當證據引用，要自己重驗。

## 五步

1. **分級**：把 finding 逐條列出，全部標待校驗。每條寫出要用什麼校驗：一個會失敗的測試、一組操作步驟加預期觀測、一行暫時的診斷輸出。
2. **去校驗**：跑。需要人操作的，一次寫清楚「做什麼、看哪裡、預期看到什麼」請人跑，讀回結果再判。跑出來升為已重現，跑不出來降為未重現。
3. **記下尺**：已重現的步驟與觀測值寫下來，之後不改動——它是修完的驗收尺，也是出事前的最後一道紀錄。校驗的輸出（測試結果、步驟與觀測值、紀錄片段）寫進回報，不是只寫「已重現」三個字。
4. **修完同一把尺再量**：用第 3 步同一組步驟重跑，前後對照。暫時加的診斷輸出驗完即移除。
5. **被推翻就還原**：修了沒差、或原因不是那個，還原那個修改，回報直接寫「判斷錯了」，不補一個新理由把它留下。

## 回報

一律兩欄：**量到的事實**、**推測**。每條帶等級（已重現／未重現）與校驗方式。未重現的也要列，讓人看到找過什麼。曾被否證的推測不再當結論提；要提，就連同否證它的紀錄一起提。

例（產業中性，僅為例）：訂單列表篩選「近三十天」後有人說「空結果沒顯示提示」。待校驗 → 用假資料把該期間清空、打開頁面 → 畫面確實空白無提示、截圖與 console 紀錄在手 → 已重現，這組步驟就是尺 → 修 → 同步驟重跑，提示出現 → 回報附前後兩張截圖。若清空後提示其實有出現，就是未重現：回報「未重現，試了清空近三十天資料」，不改 code。

## 不做什麼

- 不教怎麼建重現迴路（失敗測試、腳本、二分、差異比對這些技巧）——要完整方法論，裝 Matt Pocock 的 `diagnosing-bugs` 與本套合用。
- 不管測試怎麼寫（`tdd` 的事）。
- 不管怎麼修——已重現之後修在哪裡、算不算 workaround，接給 `root-causing`。
- 不決定找到的問題要不要全修——那是宿主慣例與使用者的決定。
