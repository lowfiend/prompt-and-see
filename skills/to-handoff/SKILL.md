# to-handoff — 真相 → 交付

交付單位是**整個需求資料夾**（`behaviors/<slug>/`），加上設計系統文件（若 `behaviors/config.md` 有設定）。本 skill 生成資料夾裡的 `handoff.md`——它是**導讀（manifest）**，不是內容的複本：真相看同資料夾的 `*.feature`、圖看 `map.md`、畫面開 `mvp/`。

## 前置檢查

- `map.md` 必須 `狀態: 已凍結`，否則停。
- 場景檔比地圖或 MVP 新（時間戳比對）→ 先重生過期產物，再生成導讀，並在變更摘要說明。**過期的產物是謊言，不准打包。**

## handoff.md 的內容（導讀四件事）

1. **版本與變更摘要**：檔頭標版本；與上一版的行為差異（新增／修改／移除了哪些場景），讓下游一眼辨識新鮮度。
2. **關鍵決定與依賴**：轉錄地圖檔頭的關鍵決定與依賴——下游不用先開圖就知道「為什麼長這樣」「要先有什麼」。
3. **交付清單（manifest）**：本資料夾內容物逐項列出；`config.md` 有設定設計系統文件就一併列入。清單以 config 的實際設定為準——**缺任何一件列出的項目，即為不完整交付**。
4. **角色使用說明**：
   - **交 QA**：場景即測項，逐條驗（假設／當／那麼＝前置／操作／預期）；發現場景漏了行為，**不得只補在測試裡**——回報行為負責人，回場景檔 `/remap` 後重新生成，測項才算數。
   - **交 UIUX review**：MVP 是「產出」，review 是**審查把關，不是重刻**；純視覺意見直接回饋，涉及行為的意見回場景檔討論。
   - **交 RD**：照地圖施工，地圖上沒有的行為不要做；**文案與版面的唯一參照是 MVP**（場景沒釘死的文字以 MVP 為準，不自行發明）；想加行為先回場景檔（`/map-it` 或 `/remap`）。

## 鐵律

- 檔頭聲明：「本檔為重新生成的產物，手改無效；要改行為請改場景檔。」
- **不內嵌場景全文與地圖**——同資料夾就有活的真相，內嵌快照只會與它漂移打架。
- 單向生成：只讀場景／地圖／MVP，絕不反向修改它們。
- 傳遞方式：同 repo 協作給資料夾路徑即可；跨頻道傳送就打包整個資料夾（zip，含清單列出的設計系統文件），或給 repo 連結。
