# remap — 變更主持人

凍結不是終點。需求變了、QA 發現漏了、實作中踩到沒盤到的行為——都走這裡。**凍結後要改的唯一路徑就是本 skill**：改場景檔，一切重新生成。

> 設定固定在 `behaviors/config.md`；其「場景資料夾」欄位決定實際根目錄（本文以預設 `behaviors/` 行文）；沒有設定檔就用預設值。

## 流程

1. **定位**：找到對應的 `behaviors/<slug>/`——**比對用語意，不是資料夾名**：讀各資料夾 `map.md` 檔頭（狀態＋關鍵決定＋依賴）與場景標題判斷，與 `map-it` 的定位同一套紀律。
   - 找不到命中的功能 → 這可能是新需求，指路 `/map-it`。
   - 使用者描述模糊 → 先釐清，絕不通靈。
2. **訪談變更**（用 `interviewing`）：這次要改什麼行為？新增、修改還是移除？影響到哪些既有場景？把受影響的場景列給使用者看，確認範圍後鎖定——範圍外的不動。
3. **改場景檔**（守 `scenario-writing`）：把 `map.md` 狀態改回 `討論中`，然後動手改。
4. **重生地圖**（`behavior-mapping` 會自動觸發）：向使用者摘要與上一版的行為差異。
5. **找碴 → 重新凍結**：與 `/map-it` 的收尾相同；凍結時在 `map.md` 檔頭更新變更紀錄（日期＋一句摘要，最新在前，**只留最近 5 筆**——完整歷史交給 Git）。
6. **提醒下游過期**：本次凍結後場景已變，整合原型、`coverage.md`、`handoff.md` 都已過期——建議重跑 `/to-mvp`（全量重生）、`/to-handoff`。skills 不自動串接：本 skill 只標過期，重生由使用者決定下一棒。

## 硬規則

- **領域語言**：全程遵守 `domain-language`——變更訪談中若重新定義了行話，當場更新 `CONTEXT.md`。
- 只改使用者點頭的範圍；順手發現的其他問題，提出來另開變更，不夾帶。
- 不准直接改地圖、原型頁面、handoff——它們是產物，改了也會被下次生成蓋掉。
